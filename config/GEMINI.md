# Writing & Copy-Editing Rules (윤문 및 리라이팅 규칙)

사용자가 글의 윤문(문장 다듬기)이나 리라이팅을 요청할 때 아래의 **번호별 톤앤매너**를 따른다.

## 톤 프리셋 (Tone Presets)

* **1번 톤 (친근한 기술 블로그 톤, `~해요` / `~합니다` 체)**
  * 독자에게 말을 건네듯 부드럽고 이해하기 쉽게 풀어쓰는 스타일 (Velog, Tistory 등 기술 블로그용).
  * 어색한 번역투와 만연체를 다듬고, 자연스러운 구어체 호흡과 명확한 설명을 유지한다.
  * **주의**: 친근하게 풀어쓰는 것은 어미와 문장 호흡에만 적용한다. 내용의 정확도·지시 강도·범위는 원문 그대로 엄격하게 지킨다.

* **2번 톤 (담백하고 전문적인 아티클/서적 톤, `~다` 체)**
  * 군더더기 없이 명확하고 신뢰감을 주는 건조·담백한 스타일 (사내 위키, 기술 서적, 미디엄 아티클, 공식 기록용).
  * 핵심 개념과 인과관계를 간결하고 객관적인 문장으로 서술한다.

## 적용 원칙
1. 사용자가 **"1번으로 다듬어줘"**, **"2번 톤으로 리라이팅해줘"**와 같이 번호로 지정하면 해당 프리셋을 즉시 적용한다.
2. 원문의 핵심 의미, 사실 관계, 기술적 정확성은 훼손하지 않으면서 가독성과 문장 흐름만 개선한다.
3. 만약 번호 지정 없이 윤문을 요청한 경우:
   * 짧은 글/문단은 **1번 톤**과 **2번 톤** 두 버전을 함께 제시하여 선택할 수 있게 한다.
   * 긴 글이나 문서 파일 전체는 기본적으로 **1번 톤**을 우선 적용한다.

## 1번 톤 윤문 시 금지 사항 (9대 체크포인트)
문장을 부드럽게 바꾸는 과정에서 아래 9가지 왜곡이 생기지 않도록 원문과 대조한다.

1. **사실 누락 금지**: 문장을 줄이거나 요약하면서 원문의 조건, 예외, 세부 사실을 빠뜨리지 않는다.
2. **사실과 다른 내용 추가 금지**: 설명을 보태려다 원문에 없는 동작·조건·수식을 덧붙이지 않는다.
   * 예: `"재현하며"` → ❌ `"그대로 재현한"` / `"최고관리자"` → ❌ `"관리자"`
3. **원문에 없는 판단 추가 금지**: 원문에 없는 평가·가치 판단·주관적 수식어를 넣지 않는다.
   * 예: ❌ `"기준이 엄격하지 않고"`, `"높은 비중"`, `"깔끔하게"`, `"무려"`
4. **단정을 추측으로 바꾸지 않기**: 공손하게 쓰려다 원문의 확정 서술을 가능성·추측 표현으로 누그러뜨리지 않는다.
   * 예: `"실패한 것이다"` → ❌ `"실패했을 가능성이 높아요"` / `"전 API로 퍼진다"` → ❌ `"번질 수 있어요"`
   * 반대로 원문의 가능성(`"남을 수 있다"`)을 확정(`"그대로 남게 돼요"`)으로 세게 바꾸지도 않는다.
5. **정도 표현을 바꾸지 않기**: 수량, 비율, 빈도, 추세 표현을 임의로 완화하거나 과장하지 않는다.
   * 예: `"절반"` → ❌ `"절반 가까이"` / `"누락되고"` → ❌ `"빠지기도 하고"` / `"365ms다"` → ❌ `"365ms까지 올라가고 있어요"`
6. **원문에 없던 인과 추가 금지**: 독립된 두 문장이나 나열을 `"~기 때문에"`, `"~다 보니"`, `"그래서"` 등으로 임의로 묶지 않는다.
7. **범위·대상을 바꾸지 않기**: 한정어(`"만"`), 검사 범위, 적용 대상을 생략하거나 좁히고 넓히지 않는다.
   * 예: `"헤더만 읽는다"`에서 `"만"` 생략 금지 / `"이름·설명에 0개"`에서 `"이름·설명"` 생략 금지 / `"가입·인증·주문·방문에 사용"` → ❌ `"방문 기록에 사용"`
8. **절차 지시를 약하게 바꾸지 않기**: 운영 절차·필수 단계·단정 결과를 선택·권유처럼 약화하지 않는다.
   * 예: `"제거하되"` → ❌ `"지워도 되지만"` / `"비교가 0건이 된다"` → ❌ `"0건으로 나올 수 있어요"` / `"파일이 맞는지 확인"` → ❌ `"제대로 올라가 있는지 확인"`
9. **비문·어색한 표기 금지**:
   * 괄호 안에 종결어미와 쉼표+참조를 섞지 않는다 (❌ `"(...올려 둡니다, #123)"` → 문장을 분리해 `"(참고: #123)"` 또는 문장 끝에 `"(#123)"`으로 표기).
   * 의미가 겹치는 중복 표현을 쓰지 않는다 (❌ `"가장 맨 앞에서"` → `"가장 앞에서"`).
   * 목록의 굵은 이름표는 명사형으로 유지한다 (❌ `**이중 주입을 해요**:` → ⭕ `**이중 주입**:`).
   * 코드 블록, YAML 프론트매터, 링크, 기술 용어와 지칭어(`"이전 이름"` 등)는 원문을 일관되게 보존한다.

## 출력 전 자가 점검
윤문을 마치기 전에 원문과 수정문을 대조하여 위 9개 항목에 걸리는 문장이 없는지 확인한 뒤 최종 결과를 제시한다.
